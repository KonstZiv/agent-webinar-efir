# Специфікація: сайт вебінару v2

**Версія 1.0 · 21.10.2026 · живий зріз «специфікація».** Джерела: [brief.md](brief.md) (0.1), [requirements.md](requirements.md) (0.3, далі — «В§N»). Специфікація відповідає на «що будуємо і в яких межах»; правила, які перевіряються «так / ні», живуть у вимогах і тут не повторюються. Задача не суперечить специфікації; якщо мусить — спершу змінюється цей файл (за погодженням оператора, із записом у журнал).

## Призначення

Сайт `https://agent.pythoncourse.me` збирає ліди, зацікавлені в агентній розробці, і веде їх до першого заняття курсу «Агентна розробка на Python» (26.10.2026, 19:00 за Києвом). Відвідувач реєструється (запрошення на заняття, у `replay` — запис ефіру), підключає Telegram і отримує інструкцію «Зроби сам». З етапу 10 ефіру v2 замінює v1 на тій самій адресі й тій самій базі учасників (В§1).

## Незмінні рішення

- **Стек:** Python 3.14, uv, FastAPI, SQLAlchemy 2.x + Alembic, PostgreSQL, Jinja2 + HTMX 2.0.11 (файл у `static/`), pydantic-settings, httpx, markdown-it-py, python-multipart, icalendar, email-validator, anthropic (лише Issue Л); pytest, ruff, mypy, pre-commit, GitHub Actions; Railway. Пакети зафіксував фундамент; новий пакет — лише рішенням оператора (В§12).
- **Інтерфейс:** українська, звертання на «ви». Тексти — дослівно з `docs/copy.md`, `docs/materials.md`, `docs/legal/`; дата ефіру — лише з налаштувань (`EVENT_*`), не текстом у шаблонах (В§16).
- **Дані:** одна база PostgreSQL, спільна з v1; v2 її лише доповнює (В§10, В§11). Відписка видаляє учасника і все пов'язане — каскадом у базі.
- **Поведінка — налаштуваннями, не кодом** (В§14): `SITE_MODE` (`live` / `replay`) змінює лише тексти й вміст екрана успіху, розмітка сторінки однакова (В§3); відкат — режим переадресації `REDIRECT_BASE_URL` на тому самому сервісі (В§11).
- **Архітектура:** `core` (сутності, сценарії, порти-`Protocol`) не імпортує фреймворків і адаптерів; адаптери обираються налаштуваннями; глобального стану немає — застосунок збирає фабрика `create_app`. Зрізи лише додають свої файли, підключаються через `install(setup)` і не імпортують один одного; власність файлів і дозволені винятки — В§12.
- **Свідомо немає:** JS-фреймворку і збірки фронтенду (HTMX + статичний CSS); черги задач і окремих воркерів (лист — фонова задача в процесі); Redis і кількох екземплярів (обмеження частоти і кеш лічильників — у пам'яті одного екземпляра); SDK Telegram і Resend (лише httpx); облікових записів і входу (адміністратор — один Bearer-токен); сторонніх скриптів, крім Google Analytics, Turnstile і плеєра YouTube у `replay` (В§9).

## Модель даних

Повна схема з типами й обмеженнями — В§10; схема v1 — `docs/legacy-schema.md`.

| Таблиця | Що зберігає | Зв'язки й інваріанти |
| :-- | :-- | :-- |
| `participants` (v1 + поля v2) | email (унікальний, нормалізований), `unsubscribe_id`, згода (версія, час), джерело переходу (UTM, ідентифікатори кліку Google, сторінка входу, referrer, `ga_client_id`); v2: `origin`, Telegram (`tg_user_id`, `tg_username`, `tg_linked_at`), `channel_member`, `level`, `extra`, `ref_code` | `referred_by` → `participants` (очищення); один Telegram — щонайбільше одна реєстрація |
| `emails` (v1) | лист учасникові: вид, стан `pending` / `sent` / `failed`, ключ ідемпотентності, час і причина збою | → `participants`, каскад; один лист кожного виду на учасника |
| `link_tokens` (нова) | персональне посилання в бота: токен, джерело `screen` / `email`, строк дії, використання | → `participants`, каскад |
| `clicks` (нова) | переходи з листів `lesson` / `course` | → `participants`, каскад; лише резерв для S3 |

- Ревізія `0001` — дослівна копія міграції v1; `0002` лише додає (таблиці, стовпці, що можуть бути порожніми, ширші перевірки, індекси) і містить усю модель одразу — зокрема поля Ф1, Ф3 і Issue Л. Зрізи і фічі міграцій не містять.
- Усі нові поля можуть бути порожніми: запис v1 без них — нормальний стан, не помилка.

## Функціональні межі

### Робимо — обсяг ефіру M1–M10

| Зріз | Що з'являється | Вимоги |
| :-- | :-- | :-- |
| фундамент (є в репозиторії) | модель і міграції, налаштування всіх зрізів, режими, `/` (запасна сторінка), `/m/{slug}`, службові теги, `/healthz`, `/privacy`, банер cookie, режим переадресації | M1 (частина), M8, M9; В§3, В§4, В§10–В§14 |
| реєстрація і лист | форма й екран успіху, лист-запрошення, `/go/*`, `.ics`, відписка, повтор листів, `generate_lead` | M2, M3, M6, M10; В§5, В§6, В§9 |
| бот | прив'язка Telegram, перевірка підписки, посилання на матеріали | M4; В§7 |
| лічильники й експорт | два лічильники, `/admin/stats`, `/admin/export.csv` | M5, M7; В§8 |
| лендінг (живий) | `landing.html` і `landing.css` в обраному глядачами дизайні; тексти — з контексту маршруту `/` | M1; В§12, `CLAUDE.md` |

Фонові задачі: фіча-переможець голосування (одна з Ф1–Ф3) мерджиться в продакшн; Issue Л — лише демонстрація на staging з гілки PR.

### Не робимо

- **Режим `course` і все після 26.10** (A1–A5): нагадування про заняття, лист із записом, масовий лист 21.10. Бажане S1–S3 (зокрема `chat_member` і облік переходів у `clicks`) — лише окремою постановкою, якщо лишиться час.
- **Не змінюємо v1:** ні репозиторію, ні сервісу `web-v1` (після `0002` — без змінних, push і повторних деплоїв), ні наявних стовпців і перевірок схеми.
- **Логіки режимів і дат у лендінгу немає;** текстів, вписаних вручну, немає. Відео на першому екрані немає: запис — лише після реєстрації.
- **Кабінету, входу, адмін-інтерфейсу немає:** організатор працює через JSON / CSV за токеном; скрипти — поза цим репозиторієм.
- **М'якого видалення немає:** позначки «відписаний» не існує, дані людини після відписки не зберігаються.
- **Стеження немає:** відкриття і кліки листів не відстежуються, власних пікселів немає; сторінки з токенами (відписка, матеріали) Google Analytics не завантажують.
- **Даних, введених людьми, на публічних сторінках немає:** лічильники — лише числа.
- **LLM для відвідувачів немає:** `LLM_ENABLED` у продакшні вимкнено.
- **Фіксованого зсуву UTC немає:** час подій — місцевий `Europe/Kyiv`.

## Критерії якості

- **Гейти завжди зелені:** `uv run pytest`, `uv run ruff check .`, `uv run mypy src`; pre-commit; CI на `ubuntu-24.04`; `tests/test_contract.py` — на поточному етапі контракту (В§16).
- **Тести першими і без мережі:** зовнішні порти (пошта, Turnstile, Telegram, LLM) у тестах — підставні реалізації `tests/fakes.py`; PostgreSQL — службовий контейнер.
- **Тест-оракул** `tests/test_copy_oracle.py`: сторінки містять тексти `copy.md` дослівно, в обох режимах; для лендінгу — умова готовності.
- **Тест архітектури:** ядро без фреймворків і адаптерів, без імпорту між зрізами; спільні файли — лише за винятками В§12.
- **Сторінка:** 375 px без горизонтального прокручування; контраст AA в усіх файлах `static/css/`.
- **Захист і журнали** (В§15): секрети лише в змінних середовища; email у журналах маскується; шляхи з токенами — під префіксами `TOKEN_PATH_PREFIXES`; GET не змінює і не видаляє даних; `/healthz` — 200 лише з повною конфігурацією і базою.
- **Процес зрізу:** постановка → план, погоджений оператором → тести → код → рецензія в чистій сесії → staging → тег. Розбіжність постановки, специфікації і реальності — зупинка й питання операторові.
- **Розгортання:** staging `agent-next` — автодеплой із `main` після зеленого CI; продакшн — етап 10 ефіру, контракт на етапі «запуск».
